Welcome to the GFTGUX Setup Guide

This guide gets the Gravity from the Ground Up exploratory programs running on a Windows or macOS computer. No prior Python experience is needed.

GFTGUX is a companion set of eight physics and astronomy programs. Download the programs and the matching documentation, set up Python once, and start with a small example. Each simulation lives in its own folder and starts from main.py.

Already have Python and PyCharm? You can use your existing installation if it is Python 3.10 or newer. Start at Download both repositories, then connect a private environment to PyCharm.

These directions reflect the supplied GFTGUX programs and documentation archive. Individual Help pages and python main.py --help give the final word on each program's experiment settings.

1. Download the programs and documentation

  1. Visit GFTGUX-Programs. Click Code → Download ZIP, then extract the ZIP. You should see eight program folders inside GFTGUX-Programs-main.
  2. Do the same at GFTGUX-Documentation. Extract it beside the Programs folder, so the Help pages are easy to find.
  3. Put both extracted folders somewhere you can keep them, such as Documents/GFTGUX. Avoid running code directly from inside a ZIP preview.
GFTGUX/
├─ GFTGUX-Programs-main/ → PhotonOrbit/main.py, BlackHoleShadow/main.py, …
└─ GFTGUX-Documentation-main/ → PhotonOrbit/PhotonOrbit.html, …

A downloaded ZIP's outer folder may have a different suffix or name. Open it and locate the folder that directly contains PhotonOrbit and BlackHoleShadow. The two repositories are separate downloads.

2. Install Python 3.10 or newer

Python runs the simulations. Get a supported Python 3 installation from python.org/downloads if you do not already have one. For a new installation, Python 3.12 is a reasonable choice; check that packages are available for any newer version you choose.

  1. Run the Windows installer. If it offers an Add Python to PATH option, select it. Installer wording varies.
  2. Open a new Command Prompt and check the version:
python --version

If Windows opens the Microsoft Store or cannot find python, try py --version in Command Prompt. Use whichever command reports your installed Python 3.10 or newer in the environment creation step.

  1. Install Python 3 from python.org if needed. macOS's built-in system Python may be unsuitable for project packages.
  2. Open Terminal and check the version:
python3 --version
Keep the project packages in the private environment below. Installing into a system-managed Python can produce an “externally managed environment” error and may interfere with system software.

3. Create one private environment for GFTGUX

A virtual environment is a .venv folder that holds the packages used by these programs. Create it inside the extracted Programs folder, beside the eight program folders. You may share this one environment across all eight.

In File Explorer, open GFTGUX-Programs-main, click the address bar, type cmd, and press Enter. In the Command Prompt that opens, run:

python -m venv .venv

If py --version worked in Section 2 but python --version did not, use py -m venv .venv instead. You can then address the environment's Python directly as .venv\Scripts\python.exe.

Open Terminal. Type cd (including the space), drag the extracted GFTGUX-Programs-main folder into Terminal, and press Return. Then run:

python3 -m venv .venv

You can address the environment's Python directly as .venv/bin/python.

Using the full environment path in later commands avoids any need to activate it. If you move the extracted Programs folder to another location later, recreate .venv there; Python environments are tied to their location.

4. Install the packages

Most GFTGUX programs use NumPy for calculations and Matplotlib for graphs. BlackHoleShadow also needs SciPy and mpmath; its own requirements.txt lists all four. From GFTGUX-Programs-main, install that requirements file into your new environment:

.venv\Scripts\python.exe -m pip install -r BlackHoleShadow\requirements.txt

Check the installation:

.venv\Scripts\python.exe -c "import numpy, matplotlib, scipy, mpmath; print('GFTGUX packages ready')"
.venv/bin/python -m pip install -r BlackHoleShadow/requirements.txt

Check the installation:

.venv/bin/python -c "import numpy, matplotlib, scipy, mpmath; print('GFTGUX packages ready')"
Why install from one program's file? The supplied archive has a requirements.txt in BlackHoleShadow. It covers the packages used across the supplied GFTGUX suite. If the repository later adds a shared requirements file, follow the current repository instructions.

5. Open the collection in PyCharm

PyCharm is optional; the terminal commands in the next section also work. If you prefer a graphical editor, install PyCharm from JetBrains and choose its free option, if offered on the download page.

  1. Choose Open in PyCharm and select the extracted GFTGUX-Programs-main folder. Accept the trust prompt for this repository if you downloaded it from the links above.
  2. Open the project's Python Interpreter selector (usually in Settings/Preferences or the status bar). Select an existing interpreter.
  3. On Windows, select GFTGUX-Programs-main\.venv\Scripts\python.exe. On macOS, select GFTGUX-Programs-main/.venv/bin/python.
  4. Expand PhotonOrbit in the Project panel. You should see main.py, physics_photon.py, driver_photon.py, plot_photon.py, and tests/.
Open the whole Programs folder so you can switch between programs while keeping one interpreter. If a Run configuration starts in the wrong folder, set its Working directory to the particular program folder containing main.py.

6. Run your first simulation

Start with PhotonOrbit. It can draw a single photon's path around a black hole. First ask for its options; then run the default example.

From the Command Prompt still in GFTGUX-Programs-main:

cd PhotonOrbit
..\.venv\Scripts\python.exe main.py --help
..\.venv\Scripts\python.exe main.py --version
..\.venv\Scripts\python.exe main.py

From Terminal still in GFTGUX-Programs-main:

cd PhotonOrbit
../.venv/bin/python main.py --help
../.venv/bin/python main.py --version
../.venv/bin/python main.py

A graph should open and a summary should appear in the terminal. Close the graph window when finished. To try another program, change into its folder and run its main.py with the same environment's Python. Many GFTGUX programs accept --mode; PhotonOrbit and GravitationalWaveSources do not need one.

In PyCharm

Right-click PhotonOrbit/main.py and choose Run. If needed, edit the Run configuration's Working directory to PhotonOrbit. Put options such as --b 6.0 in Parameters.

Check the version

Run main.py --version from the program folder to see that program's version and Build ID. Match those identifiers against its Help or release notes if you downloaded the repositories at different times.

7. Read the documentation beside each program

Open the matching .html file in the GFTGUX-Documentation-main folder with a web browser. For PhotonOrbit, start with PhotonOrbit/PhotonOrbit.html. Its adjacent release notes and SampleOutputs/ example guide provide further context.

The program and documentation repositories use matching program names except for the cosmology folder: the code is in Cosmology_expansion_simulator while its Help is in CosmologyExpansionSimulator. Open the documentation from its own folder; you need not copy it into the code folder.

BlackHoleShadow builds on the ideas in PhotonOrbit; NbodyGalaxySimulator assumes familiarity with Multiple from the separate GFTGUX-Programs collection. You do not have to install either prerequisite program merely to launch GFTGUX, but the relevant tutorial makes the later exercises easier to understand.

9. Restore defaults and solve common setup problems

Restore a program's original settings

For a command line experiment, omit the extra options and rerun main.py; each program supplies its own defaults. In PyCharm, remove the extra Parameters from the Run configuration. If you edited a source file, use Undo before closing the editor or extract a fresh copy of that program folder from the Programs ZIP. Save any work you want to keep first. Replacing the folder restores its original code and default parameters.

If a run fails

  • “No module named …”: Confirm that the chosen Python is the .venv interpreter. Re-run the install command in Section 4 with that interpreter.
  • “Externally managed environment”: Install through .venv, not system Python.
  • “can't open file main.py”: Change into the folder of the program you want to run or adjust PyCharm's Working directory.
  • Python interpreter unavailable after moving the project: recreate .venv in its new location and select the new interpreter in PyCharm.
  • Graph does not appear: Make sure the program has finished initializing and that you are using a desktop graphical session. Read its console output and Help page; some modes can save files to an output folder instead.

When you download a new copy of either repository, compare the program's --version output with its Help and release notes. Replace both repository downloads together when possible so the explanations match the code.
