Description

GravitationalLensing teaches one equation — the thin-lens mapping \(\boldsymbol\beta=\boldsymbol\theta-\boldsymbol\alpha(\boldsymbol\theta)\) — and then asks it four increasingly interesting questions: what does a point mass do to a compact source, what does the same point mass do to an extended one, where does the mapping stop being invertible at all, and what happens once the lens is no longer perfectly round. Seven modes, one deflection law at a time, build that progression up.

The spine of the lesson is one sentence: where the source sits relative to the caustic — and, for a singular model, relative to the pseudo-caustic — decides the photograph. A point-mass lens is the chapter in which the caustic has collapsed to a single point at the origin: on it, a ring; off it, two images, always. A singular isothermal sphere with a little external shear is the chapter in which that point opens into a diamond with four folds and four cusps, and the number of images becomes a genuine function of where the source is.

What this program is not. It does not integrate a single null geodesic anywhere — that is PhotonOrbit's job, and BlackHoleShadow's. The thin-lens deflection here is applied at one plane, once, as a small-angle kink; it has no critical null geodesic in it and therefore no black-hole silhouette, which is the entire content of Beat 4's warning and of BlackHoleShadow's own Beat 8. It does not fit a mass model to any real image. Galaxy-scale strong lensing, at Einstein radii of order an arcsecond, is the intended domain.
False colour, always. Modes point, blob, critical, arcs and kappa paint intensity or convergence with a colour map. Those colours are a display scale, not the spectrum of the source. Gravitational deflection is achromatic: neither a point mass nor a singular isothermal sphere splits light into a rainbow the way a glass prism does. A white galaxy stays white; the palette exists only so a faint arc is visible on a screen.
Reading this page. Equations are rendered by MathJax, loaded from a public CDN, so an internet connection is needed to see them typeset; offline, the raw \(\LaTeX\) source shows as plain text instead. The program itself needs no internet access to run. A blue DERIVED tag marks an equation obtained algebraically from the thin-lens equation once a deflection law is fixed. A violet CLOSURE tag marks a mass model chosen for teaching convenience rather than fitted to any particular galaxy: this program uses exactly one, the singular isothermal sphere plus external shear of Beats 5–7. There are no integrated differential equations, no empirical fits and no adopted rules distinct from the deflection laws themselves anywhere in this program — the whole calculation is algebra once a mass model and a source position are chosen, which is a real difference from BlackHoleShadow's integrated null geodesics and from StellarEvolutionTracks's evolution equations, and worth noticing precisely because it is not the same kind of program.

Before the first run

Unpack the program zip so you have a folder named GravitationalLensing containing main.py, and open a terminal there. You need Python 3.10 or newer with NumPy and Matplotlib only — no SciPy, no mpmath, unlike BlackHoleShadow, because nothing in this program requires arbitrary-precision arithmetic or quadrature. If you do not already have that environment, follow the project-wide GFTGUX Python Setup Guide, and do not install packages into a system Python (PEP 668). Then:

python main.py --version
python main.py --mode rays

Every command on this page assumes that working directory. Source positions and the field of view are in arcseconds; masses are entered as \(\log_{10}(M/M_\odot)\), never as a raw solar-mass number, specifically so a run cannot silently be off by many orders of magnitude. Even values of --n_pix are rounded up to the next odd number, so a pixel always sits on the optical axis. There is no --csvdir option in this program; a run produces a figure and, optionally, a saved PNG.

How to read this page

Each numbered section below is one beat: a short argument, a command whose figure is the evidence, and then the equation the figure has earned. Do them in order the first time — the progression matters here more than usual, since Beat 4 (the caustic of a point mass) is deliberately the trivial case that Beats 5–7 then complicate. After that, any mode can be opened on its own.

This is a smaller program than StellarEvolutionTracks or even BlackHoleShadow: one deflection law at a time, no integration, no arbitrary-precision arithmetic. The beats are correspondingly about what a fixed piece of algebra implies as the mass model is made less symmetric, rather than about new machinery.

Beat 0 · Rays, no jargon

Start before any of the vocabulary — Einstein radius, caustic, convergence — is introduced. A glass lens bends a ray more the further it passes from the centre. A point-mass gravitational lens does the opposite: a ray that skims close to the mass is bent hard, a ray that passes far away is barely bent at all. The observer does not sit at any kind of focus; the observer simply happens to be wherever the bent rays land.

python main.py --mode rays

Two panels, both tracing rays forward from a single source toward a fixed observer. On axis, the symmetry of a point mass makes every azimuth around the line of sight equivalent, so there is exactly one deflection angle that lands a ray on the observer regardless of which way around the mass it passes — a whole cone of rays qualifies, and the side view shows one slice of that cone as two red rays that happen to look like a simple double. Move the source off axis and the symmetry breaks: now only two specific rays, one passing above the mass and one below, survive to reach the observer, one on each side.

Three tasks, in order. First find the kink in each red ray at the lens plane, and confirm every kink bends toward the mass — gravity only attracts, so there is no ray in this figure bent away from the lens. Then compare the on-axis and off-axis panels and say, in one sentence, what has changed about the observer's rays (not about the lens). Then note the vertical scale: for the default \(10^{12}\,M_\odot\) lens, \(\theta_E\) is only a few times \(10^{-5}\) radians, so the whole figure is drawn at a schematic vertical exaggeration; nothing about the horizontal geometry is to scale either, since \(D_l=D_{ls}=1\), \(D_s=2\) in these units are chosen for a clean picture, not a real distance ratio.

Then the one idea the rest of this program exists to make quantitative: an observer does not see a lens in the way a camera sees a subject through a glass lens. An observer sees whichever directions happen to satisfy one equation — the lens equation, earned properly in Beat 1 — and everything from the Einstein ring to a four-image quad is a different way that equation can be satisfied.

Experiments that go with this beat: EXP-1 in Suggested Experiments.

Beat 1 · A point mass on the sky

Now draw the same geometry the way an observer actually sees it: as a picture on the sky, not a side view. The default source is already off-axis, so the very first frame is a double, not a ring.

python main.py --mode point
python main.py --mode point --beta_x 0.0 --beta_y 0.0
python main.py --mode point --logM 12.5 --beta_x 0.3 --beta_y 0.3
Point-mass Einstein radius DERIVED
\[\theta_E=\sqrt{\frac{4GM}{c^2}\,\frac{D_{ls}}{D_lD_s}}.\]
Lens equation DERIVED
\[\boldsymbol\beta=\boldsymbol\theta-\boldsymbol\alpha(\boldsymbol\theta),\qquad \boldsymbol\alpha(\boldsymbol\theta)=\theta_E^2\,\frac{\boldsymbol\theta}{|\boldsymbol\theta|^2}.\]

Three tasks, in order. First rerun with --beta_x 0 --beta_y 0 and read off the figure: the source sits exactly on the lens, and the false-colour image is now a complete ring at radius \(\theta_E\). Then read the default run's Einstein radius from the dashed cyan circle: for a \(10^{12}\,M_\odot\) lens at the cartoon distances, \(\theta_E=2.018''\), and check that the white cross marking the unlensed source — at the default \((0.50'',0.00'')\) — sits well outside that circle. Then raise the mass with --logM 12.5 and watch the ring grow to \(\theta_E=3.588''\); the field of view grows with it automatically so the ring is never clipped.

Then the arithmetic behind the two commands above. For a source at angular offset \(\beta\) along one axis, the lens equation has a closed-form solution:

Analytic double for a source on-axis DERIVED
\[\theta_\pm=\frac12\left(\beta\pm\sqrt{\beta^2+4\theta_E^2}\right).\]

At the default \(\beta=0.50''\) and \(\theta_E=2.018''\), this gives \(\theta_+=2.283''\) and \(\theta_-=-1.783''\): an outer image outside the ring and an inner image on the opposite side of the lens, exactly as the figure shows. The magnification of each image, \(\mu=1/\det A\), works out to \(\mu_+\approx+2.56\) and \(\mu_-\approx-1.56\): the outer image is brighter than the source and keeps its orientation (positive parity), the inner image is fainter and mirror-reversed (negative parity) — and, notice, \(|\mu_+|-|\mu_-|=1\) exactly, a general identity for any transparent axially symmetric lens with no matter between the two images, not a coincidence of these particular numbers.

Units, stated plainly. \(G\) and \(c\) are SI; mass is entered as \(\log_{10}(M/M_\odot)\) specifically so a slip of several orders of magnitude cannot pass silently — a mass entered as a raw number of kilograms or solar masses would be exactly that kind of slip. The compact source's own width is held fixed at \(0.08''\) throughout point, far smaller than any Einstein radius used on this page, so the images it forms are close to the point-source ideal of the formulae above.

Experiments that go with this beat: EXP-2 and EXP-8 in Suggested Experiments.

Beat 2 · Why two, always

A transparent point mass never produces one image of an off-axis source, and never produces three. It is worth knowing why before moving to a lens that can.

Look again at \(\theta_\pm=\tfrac12(\beta\pm\sqrt{\beta^2+4\theta_E^2})\) from Beat 1. The quantity under the square root, \(\beta^2+4\theta_E^2\), is strictly positive for any finite \(\beta\) and any \(\theta_E>0\): there is no source position at which it vanishes, and no source position at which it has only one real root instead of two. A point mass's lens equation is quadratic in \(\theta\) along any line through the origin, and a quadratic with a positive discriminant always has exactly two roots. That is the whole reason a point-mass lens is "two, always" while the shear-broken lens of Beat 5 can be one, two, or four depending on where the source sits.

Parity, precisely. The sign of \(\det A\) is the image's parity. Positive parity preserves the source's orientation; negative parity mirrors it, the way a plane mirror does, not the way negative brightness would (there is no such thing as a negative flux). For a point mass the outer image (\(\theta_+\)) is always positive parity and the inner image (\(\theta_-\)) always negative, independent of \(\beta\) and \(\theta_E\) — only the two magnitudes \(|\mu_\pm|\) change with the source position.

Beat 3 · An extended blob, still a point mass

Replace the compact source with a small elliptical Gaussian galaxy and change nothing about the lens. The lens equation does not know or care whether the light it is bending comes from a point or an extended object; only the picture does.

python main.py --mode blob
python main.py --mode blob --beta_x 0.0 --beta_y 0.0
python main.py --mode blob --beta_y 0.8 --r_eff 0.20

A centred extended source becomes a thick ring rather than two dots, because every azimuth of the source's light satisfies the on-axis lens equation at once, at slightly different radii for the near and far edges of the galaxy. Shift the source off-axis and that ring splits into two arcs — literally the same forward-ray geometry as the lower panel of --mode rays, now rendered as a photograph of an extended object rather than sketched as two rays.

Then the sentence this beat exists to set up. For a point-mass lens, the source plane has exactly one distinguished point: the origin, \(\beta=0\). A source there becomes a ring; a source anywhere else, however close, becomes exactly two images (Beat 2), never more, never fewer. Naming that one point properly — the caustic — is Beat 4's job, and having watched an extended source pass through it here first makes the definition land as something you have already seen rather than a new piece of jargon.

Experiments that go with this beat: EXP-3 in Suggested Experiments.

Beat 4 · Name the critical curve, and look at the rays that make the caustic

The lens mapping sends every sky position \(\boldsymbol\theta\) to a source position \(\boldsymbol\beta(\boldsymbol\theta)\). Its Jacobian \(A=\partial\boldsymbol\beta/\partial\boldsymbol\theta\) is a \(2\times2\) matrix at every point on the sky, and the signed magnification is simply its inverse determinant.

Signed magnification DERIVED
\[\mu=\frac{1}{\det A}.\]

The sign of \(\mu\) is the image's parity, exactly as in Beat 2; the factor that multiplies observed flux or area is \(|\mu|\), never \(\mu\) itself — negative parity is a mirror, not negative brightness. For an idealised point source, \(|\mu|\to\infty\) is achievable in principle; a finite source, such as every blob in this program, always has a finite observed magnification because it averages \(\mu\) over its own finite area.

Where \(\det A=0\), that stretch factor formally diverges for a point source. That locus, drawn on the sky, is the critical curve. Push the same locus through the lens equation into the source plane and the image is the caustic. A caustic is not a physical object sitting anywhere in space; it is a curve in the source plane marking where the lens mapping's image multiplicity is about to change.

Two planes, never confused. The critical curve lives in the image plane — the sky an observer actually looks at. The caustic lives in the source plane — a plane no observer can look at directly, since it is defined by the unlensed position of a source whose only light we ever receive has already been bent. The lens equation is the map from one to the other; they are not two views of the same curve.
Point-mass Jacobian determinant DERIVED
\[\det A=1-\left(\frac{\theta_E}{|\theta|}\right)^{4}.\]

The zero set of this expression is exactly the Einstein circle \(|\theta|=\theta_E\) — the critical curve is the dashed ring from Beat 1, now given a reason to exist rather than just a formula. Push it through the lens equation and it collapses to the single point \(\beta=0\): the caustic of a point mass really is one point, confirming what Beat 3 already showed by demonstration.

python main.py --mode critical
python main.py --mode critical --beta_y 0.4

Mode critical draws three panels at once: the photograph with the critical curve overplotted, the source plane with the caustic marked as a star at the origin, and a side view of the same source using Beat 0's forward-ray convention (red rays reach the observer, blue rays miss) rather than a Schwarzschild geodesic. The side view is a slice through a genuinely three-dimensional geometry; motion in \(\beta_x\) points into or out of the page and is invisible in this projection, so the coordinate that actually changes the side-view picture is --beta_y. Changing --logM only resizes a self-similar circle and teaches nothing new about this beat; the coordinate worth varying here is the source position.

Beat 5 · Break the symmetry

A real lensing galaxy is not a point mass, and Beat 2's "two, always" is a consequence specifically of the point mass's perfect circular symmetry, not of lensing in general. Break that symmetry with the cheapest model that still has a closed-form deflection: a singular isothermal sphere plus a uniform external tidal field.

SIS + shear deflection CLOSURE
\[\boldsymbol\alpha=\theta_E\,\hat{\boldsymbol\theta}+(\gamma\,\theta_x,\,-\gamma\,\theta_y).\]

The critical curve opens from a circle into an oval on the sky. The caustic opens from a single point into a diamond in the source plane, with four sharp cusps and four smooth folds joining them. At the default \(\gamma=0.25\), the diamond is not round: two cusps sit on the \(\beta_y\)-axis at \(|\beta|=\tfrac23\theta_E\), while the nearest points on the connecting folds pull in to about \(0.275\,\theta_E\) along the diagonals and the curve crosses the \(\beta_x\)-axis at \(0.40\,\theta_E\). Moving the source without crossing either the caustic or a second boundary described next merely moves the existing images continuously; crossing either boundary changes how many images there are.

Because the SIS mass model is mathematically singular at its own centre, there is a second boundary in addition to the caustic itself: the pseudo-caustic, the image in the source plane of that central singularity, a circle of radius exactly \(\theta_E\) (independent of \(\gamma\)). Outside it, only one image survives — the missing image has effectively merged into the central singularity and vanished, a consequence specifically of the SIS's singular density profile; a galaxy with a finite-density core would behave differently there. The image count therefore changes at two different curves, not one, and the table below is the whole of it for \(|\gamma|<1/3\), the range this program allows so that the diamond always stays safely inside the pseudo-caustic and no "naked cusp" three-image region appears.

SourceImagesWhat happened
outside the pseudo-caustic1the second image has fallen into the central singularity
between the pseudo-caustic and the diamond2the source missed the diamond entirely

python main.py --mode shear --beta_x 0.55 --beta_y 0.10
python main.py --mode shear --beta_x 0.05 --beta_y 0.03
python main.py --mode shear --beta_x 2.0 --beta_y 0.0
python main.py --mode shear --gamma 0 --beta_x 0 --beta_y 0

Three tasks, in order. First run the four commands and count the numbered dots on the left panel of each: 2, 4, 1, and a ring, in that order — the second command is the program's own default source position, deliberately placed deep inside the diamond so the very first shear run a student makes is already a quad. Then find the dashed pseudo-caustic circle on the right panel of each run and confirm the first source sits outside the diamond but still inside that circle (2 images), the third sits well outside even the pseudo-caustic (1 image). Then explain, from the deflection law above, why setting --gamma 0 at the origin recovers exactly Beat 1's Einstein ring: with no shear, the SIS deflection alone is axially symmetric, and an axially symmetric lens with the source on the caustic always rings.

Beat 6 · Arcs, as a fat source on the same diamond

Keep the SIS-plus-shear lens exactly as it was in Beat 5, and light it with an extended elliptical source instead of a point. The image-count table of Beat 5 still governs everything; it simply now applies to every point of an extended galaxy at once, and adjacent points near a fold or cusp are stretched into a continuous arc rather than remaining separate dots.

python main.py --mode arcs
python main.py --mode arcs --beta_x 0.55 --r_eff 0.14
python main.py --mode arcs --beta_x 0.00 --beta_y 0.00 --r_eff 0.20
python main.py --mode arcs --gamma 0 --beta_x 0 --beta_y 0 --r_eff 0.20

Drape the source on a fold and two long arcs appear, roughly parallel to the critical curve at that point. Drape it near a cusp and one of the two arcs splits into the crowded three-image group Beat 5's table names. Park it at the origin with the default shear and the result is four shorter arcs strung around the oval critical curve — broken symmetry again, not a ring, because the shear is still there. Only the fourth command, with the shear removed, recovers a genuinely circular ring: a reminder that a real extended arc's exact shape is telling you about the local shear and convergence at the point where it forms, which is exactly the diagnostic real strong-lensing observers use to reconstruct a cluster's mass distribution.

Experiments that go with this beat: EXP-6 in Suggested Experiments.

Beat 7 · Only now: what \(\kappa\) is

Every earlier beat has used the SIS deflection without ever drawing the mass distribution that produces it. That is deliberate: by the time the mass map itself appears, its consequences — the critical curve, the diamond, the image-count table — already mean something, and the map is no longer an abstract density profile but the explanation for pictures already seen.

Convergence DERIVED
\[\kappa(\boldsymbol\theta)=\frac{\Sigma(\boldsymbol\theta)}{\Sigma_{\rm crit}}.\]

\(\kappa\) is projected surface mass density in units of the critical surface density for lensing at the assumed distances — a dimensionless convenience, not a real areal density in \(\rm kg\,m^{-2}\). For the singular isothermal sphere used throughout this program, \(\kappa=\theta_E/(2|\theta|)\), and on the Einstein circle itself \(\kappa=1/2\) exactly — which is exactly where the (unsheared) critical curve sits.

python main.py --mode kappa
python main.py --mode kappa --sigma_v 180

Mode kappa draws the SIS mass map with that \(\kappa=1/2\) circle traced on top, so the coincidence is visible rather than merely asserted. Raising or lowering --sigma_v rescales the whole map, since \(\theta_E\) itself depends on \(\sigma_v\), but the relation "critical curve where \(\kappa=1/2\)" never changes — which is exactly why this mode was saved for last: nothing about it is new physics, only a new picture of a quantity every earlier beat had already used.

SIS Einstein radius DERIVED
\[\theta_E=4\pi\left(\frac{\sigma_v}{c}\right)^{2}\frac{D_{ls}}{D_s}.\]

At the default \(\sigma_v=300\,{\rm km\,s^{-1}}\) this gives \(\theta_E=1.298''\); at \(\sigma_v=180\,{\rm km\,s^{-1}}\) it falls to \(\theta_E=0.467''\), scaling as \(\sigma_v^2\) exactly as the formula says (\((180/300)^2=0.36\), and \(0.467/1.298=0.360\)). \(\sigma_v\) is entered in \(\rm km\,s^{-1}\) and converted to \(\rm m\,s^{-1}\) before use for the same reason mass is entered as \(\log_{10}(M/M_\odot)\) in the point-mass modes: a label of "km/s" attached to a raw value of 200 compared against \(c=3\times10^8\,{\rm m\,s^{-1}}\) is a thousandfold error waiting to happen, and the program does the conversion so the student never has to remember to.

Algorithm

Modes rays, point, blob

  1. Validate the mass or shear parameters, the source position, and the grid.
  2. Compute the Einstein radius for the requested mass at the fixed cartoon distances.
  3. For rays: build a small bundle of rays at fixed launch heights, apply the point-mass kink at the lens plane, and classify each as a hit (reaches the observer within a small tolerance) or a miss; draw both bundles, on-axis and off, in one figure.
  4. For point or blob: evaluate the point-mass deflection at every pixel of the image-plane grid, subtract it from the pixel's own sky position to get the corresponding source-plane position, and sample the source's brightness profile (compact Gaussian, or the elliptical Gaussian for blob) there. This is image-plane ray shooting, the standard and numerically robust way to render an extended lensed image; it needs no root-finding because the point-mass deflection can be evaluated in closed form at every pixel directly.
  5. Refuse a grid that cannot resolve both members of the point-mass double to at least a fraction of a pixel interval, naming which image (inner or outer) is compressed and by how much.

Mode critical

  1. Evaluate the point-mass Jacobian determinant on the image-plane grid and extract its zero contour as the critical curve.
  2. Push that curve through the lens equation to obtain the caustic (a single point, to within numerical tolerance, for a point mass).
  3. Separately build the Beat-0-style forward-ray side view for the requested source position.

Modes shear, arcs

  1. Evaluate the closed-form tangential critical radius \(r(\phi)=\theta_E(1-\gamma\cos2\phi)/(1-\gamma^2)\) at a dense grid of azimuths \(\phi\) to trace the (oval) critical curve directly, without a numerical root search.
  2. Push that curve through the SIS+shear lens equation to obtain the diamond caustic, and evaluate the fixed-radius pseudo-caustic circle at \(\theta_E\).
  3. For shear: locate every image of the requested source by Newton's method, started from a ring of initial guesses around the expected image radii, converging each candidate to the lens equation \(\boldsymbol\beta(\boldsymbol\theta)=\boldsymbol\beta_{\rm src}\) to a tight tolerance, then de-duplicating solutions that converged to the same point.
  4. For a source close enough to the origin and with \(\gamma=0\) that it is, to within a small tolerance, exactly the Einstein-ring case, skip the discrete image search and draw the ring directly instead — a genuine ring cannot be represented as a finite list of point images, so the program does not try to force one.
  5. For arcs: shoot every pixel of an extended elliptical source through the same SIS+shear deflection, exactly as blob does for a point mass.

Mode kappa

  1. Evaluate the closed-form SIS convergence \(\kappa=\theta_E/(2|\theta|)\) on the image-plane grid.
  2. Refuse a field of view / pixel combination in which the Einstein circle would span fewer than four grid intervals, naming the shortfall and suggesting a larger --sigma_v.
Why there is no quadrature or high-precision arithmetic anywhere in this program. Every deflection law used here — point mass, and SIS plus a uniform shear — has a closed-form inverse or a closed-form critical curve. Nothing needs to be integrated along a ray, and nothing needs arbitrary precision the way BlackHoleShadow's near-critical rays do, because no quantity in this program is the difference of two nearly equal large numbers. The one place this program does real numerical work is the Newton solver in shear mode, and even that is solving a low-dimensional algebraic system, not tracing a trajectory.

Module Overview

Engine
physics_gl.py

Einstein radii for both mass models, both deflection laws and their Jacobians, the analytic point-mass double, the SIS+shear critical curve and caustic in closed form, the Newton image finder, the source brightness profiles, and the thin-lens forward-ray bundles used by rays and critical. All input validation lives here.

Figures
plot_gl.py

One drawing routine per mode. With --outdir, writes a timestamped PNG and a same-stem .provenance.txt sidecar recording the version, build, and the run's own parameters.

Driver
driver_gl.py

Builds the image-plane grid, calls the engine for the selected mode, and hands the results to the plotter. Setting MPLBACKEND=Agg suppresses the on-screen window, which is how this program's own test suite runs headless.

Entry Point
main.py

The argparse command line, including the mode-dependent default source positions (Beat 1's ring-breaking \(0.50''\) offset, Beat 5's deep-quad default, and so on), and conversion of validation or runtime failures into concise command-line error messages.

Parameters

Run python main.py --help for the current command summary, and python main.py --version for the model version, which every saved figure's own footer also repeats. Options that do not apply to the selected mode do not change its results.

Output and Plot Panels

OutputWhat to look for
raysTwo stacked panels, on-axis then off-axis, each a forward-ray side view. Red rays reach the observer; blue rays miss. Titles state directly what changed between the two panels.
pointA false-colour image with the dashed Einstein circle and the white source cross both overlaid, so the ring or double and the geometry that produced it are on the same picture.
blobThe same overlay style as point, now with an extended galaxy in place of a compact source — a thick ring on axis, two arcs off it.
criticalThree panels: the image plane (false colour, critical curve overplotted, titled to note the critical curve equals the Einstein ring for a point mass), the source plane (caustic marked as an enlarged point symbol at the origin), and a forward-ray side view using \(\beta_y\).
shearTwo panels: the image plane, with every located image numbered and colour-coded (or the Einstein ring drawn directly, in the degenerate case), and the source plane, with the diamond caustic, the dashed pseudo-caustic circle, and the source itself marked. The image-plane title states the image count directly.
arcsA false-colour extended image with the oval critical curve overplotted, so an arc's proximity to that curve is visible directly rather than left to be inferred.
kappaThe SIS convergence map in false colour, with the \(\kappa=1/2\) circle traced on top, coinciding exactly with the (unsheared) critical curve.
PNG and provenanceWith --outdir PATH: a timestamped PNG and a same-stem .provenance.txt sidecar recording the mode, the version, the build, and the run's own parameters (image count for shear, Einstein radius, source position, and so on), so a saved figure can always be traced back to the command that produced it. There is no CSV output in this program and no console summary either — unlike BlackHoleShadow and StellarEvolutionTracks, every number this program reports is read directly off the figure itself, which is why the figures are annotated as heavily as they are.

Suggested Experiments

Nothing here needs anything beyond the program itself, a ruler held up to the screen, and occasionally a pocket calculator. There is no fitting, no calibration and no convergence study to run, because nothing in this program is integrated or fitted in the first place; the numerical judgement these exercises ask for is entirely about reading a picture correctly.

Introductory

EXP-1

Two Panels, One Kink

Run --mode rays. In one sentence for each panel, say what changed about the observer's rays between the on-axis and off-axis cases, being careful not to describe it as something that changed about the lens.

EXP-2

Two, Always

Run --mode point at three different \(\beta_y\) values, including \(\beta_y=0\). Using the analytic formula \(\theta_\pm=\tfrac12(\beta\pm\sqrt{\beta^2+4\theta_E^2})\), compute \(\theta_+\) and \(\theta_-\) by hand for each and check them against the figure. Explain, from the discriminant of that formula, why a point-mass lens can never produce one image or three for a source at finite \(\beta\).

EXP-3

A Ring Has No Preferred Direction

Run --mode blob --beta_x 0 --beta_y 0, then --mode blob --beta_y 0.8 --r_eff 0.20. Describe in words what "the caustic is a single point" implies about the first image, and what it implies about how abruptly the ring breaks into two arcs as the source moves off that point by even a small amount.

EXP-4

Two Planes, Never Confused

Run --mode critical. Point to the critical curve and say which plane it lives in; point to the caustic and say which plane it lives in. Then explain why an observer can point a telescope at the first but never directly at the second.

Intermediate

EXP-5

Crossing the Diamond

Reproduce Beat 5's four shear commands and record the image count each time. Then find, by trial, a fifth source position that crosses from 2 images to 4 by moving only --beta_y at fixed --beta_x 0.4, and identify which boundary (fold or pseudo-caustic) you crossed.

EXP-6

An Arc Is a Local Measurement

Run --mode arcs --beta_x 0.55 --r_eff 0.14 (near a fold) and --mode arcs --beta_x 0.00 --beta_y 0.00 --r_eff 0.20 (near the cusp cluster). Compare the two sets of arcs and describe, in your own words, what is different about the local critical curve near a fold versus near a cusp that produces the difference you see.

EXP-7

Convergence at the Ring

Run --mode kappa at two different --sigma_v values and confirm the Einstein radius scales as \(\sigma_v^2\), using the closed-form SIS formula. Then explain, from \(\kappa=\theta_E/(2|\theta|)\), why \(\kappa=1/2\) at \(|\theta|=\theta_E\) for any value of \(\sigma_v\) — the coincidence that kappa mode exists to make visible.

EXP-8

Magnification Adds Up

At the default point source position, compute \(\mu_+\) and \(\mu_-\) from \(\mu=1/\det A\) and confirm \(|\mu_+|-|\mu_-|=1\). Then repeat at a second \(\beta\) of your choosing and confirm the identity still holds. This is a general property of any transparent, circularly symmetric lens; look up (or derive, if you know the trick) why it must be exactly 1 and not merely close to it.

Advanced

EXP-9

The Pseudo-Caustic Is Not the Caustic

Using --mode shear, place the source just inside the pseudo-caustic circle but well outside the diamond (2 images), then just inside the diamond near a fold (4 images), and read the image-plane panel each time for where the extra pair of images appeared. Explain why the image count changes at two different boundaries for this singular mass model, and what physically distinguishes "falling into the singularity" from "crossing a fold" as ways for an image to appear or disappear.

EXP-10

Where the Formula in Beat 5 Comes From

Beat 5 states the cusp locations at \(|\beta|=\tfrac23\theta_E\) on the \(\beta_y\)-axis and the fold's closest approach near \(0.275\,\theta_E\) on the diagonals, for the default \(\gamma=0.25\). Using the closed-form critical radius \(r(\phi)=\theta_E(1-\gamma\cos2\phi)/(1-\gamma^2)\) and the SIS+shear lens equation, reproduce those two numbers by evaluating the critical curve at \(\phi=90^\circ\) and \(\phi=45^\circ\) and pushing each point through the lens equation by hand. Then predict, before running it, whether the cusps move closer to or farther from the origin as \(\gamma\to1/3^-\), and check your prediction against --gamma 0.30.

Synthesis

EXP-11 · synthesis

One Equation, Seven Pictures

Make a table with one row per mode, giving the deflection law it uses, the beat that earns that law, and the one sentence that mode exists to demonstrate (a symmetry, a boundary, a count, a coincidence). Then write, in no more than four sentences, what changed about the physics between Beat 4 (a point mass) and Beat 5 (SIS plus shear) — not what changed about the picture, but what property of the mass distribution is responsible for the image count becoming a genuine function of source position instead of a constant.

Domain of Validity

  • Thin lens, small angles. Fine for galaxy-scale strong lensing at arcsecond Einstein radii; not a strong-field ray tracer. It shares no machinery with, and cannot reproduce, BlackHoleShadow's critical null geodesics — Beat 4 states this directly, and BlackHoleShadow's own Beat 8 makes the scale gap numerically explicit.
  • Fixed cartoon distances, \(D_l=1\,{\rm Gpc}\), \(D_s=2\,{\rm Gpc}\), chosen only so Einstein radii come out at a few arcseconds for a teaching example. They are not a cosmological model, and real angular-diameter distances are not in general related by \(D_{ls}=D_s-D_l\) the way this program's flat cartoon assumes.
  • SIS plus external shear is the cheapest lens with a diamond caustic, not an elliptical mass profile fitted to any real cluster or galaxy. The particular \(\sigma_v\) and \(\gamma\) used on this page describe no specific observed system.
  • The Newton image finder is exercised, in this Help file, only in the one-, two- and four-image regions that Beat 5's table covers. Within about \(10^{-4}\,\theta_E\) of a fold or cusp, images are merging and the count itself is not a promised teaching output at that precision.
  • No console summary. Every number this program reports is annotated on the figure itself (an Einstein radius, an image count, a magnification read from the plotted markers); there is nothing printed to the terminal beyond --version and error messages, which is different from both BlackHoleShadow and StellarEvolutionTracks and is worth knowing before searching a terminal window for a number that is actually on the plot.

Restoring Default Parameter Values

If you edit main.py or another program file while experimenting, you can restore the original program files using any of the following methods:

  • Same session: Press Ctrl+Z (Windows) or Cmd+Z (macOS) repeatedly in your editor to undo your edits.
  • If you are using PyCharm: Right-click the edited file in the Project panel → Local History → Show History → select a version from before your changes → click Revert.
  • Full reset: Re-download the ZIP from github.com/tomyee3-org/GFTGUX-Programs and replace this program's folder with the fresh copy.

For additional ways to restore program files, see the corresponding recovery instructions in the GFTGUX Python Setup Guide.
