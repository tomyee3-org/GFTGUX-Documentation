GravitationalLensing 1.3.0 Release Notes

Version: 1.3.0; Build: e30d2c36ae1a; Date: 2026-11-01.

Release Status

Version 1.3.0 is approved following Kickoff7 and the independent Audit71 reviews dated 2026-10-26. Claude recommends APPROVE with three optional P3 observations, all rated OK, and nine optional P4 observations. Grok recommends APPROVE with two optional wording notes. Neither reviewer identified a release-blocking finding. This documentation completion records those outcomes and updates the Sample Outputs Guide; the audited Help, core code, tests, version and build are unchanged.

Open Bugs

  • GL-71-01 — P3 OK; Claude P3-1. The critical-mode source-plane panel has no legend, and its star denotes the caustic while stars denote sources in rays/shear modes.
    python main.py --mode critical --beta_x 0 --beta_y 0.4: observed an unkeyed blue star and purple cross; expected an explicit panel/Help marker key. The updated Guide supplies a key, but the figure and Help observation remains open.
  • GL-71-02 — P3 OK; Claude P3-2. A large-mass point/critical run can suggest moving an already centred source closer.
    python main.py --mode point --logM 13: observed a 401-pixel-limit rejection followed by “Move the source closer to the lens”; expected a remedy applicable to the centred source.
  • GL-71-03 — P3 OK; Claude P3-3, Help portion. Beat 6’s “Intermediate position” command lacks its own interpretation.
    Open Help Beat 6 at --beta_x 0.18 --beta_y 0.00 --r_eff 0.25: observed a command without a description of its four bright knots/broken ring; expected that interpretation. The Guide portion is corrected here; the Help portion remains open.

Major Improvements in This Release

  • The 1.2.0 maintenance round made --beta_x and --beta_y default to zero in every mode, including partial-coordinate inputs and direct driver calls.
  • The 1.3.0 code round made --outdir save PNG/provenance files in addition to normal display, corrected singular-centre intensity/convergence rendering, preserved outer convergence values, aligned the critical-mode ray slice with the full source offset, and stabilized ideal magnifications for tested tiny nonzero offsets.
  • The merged Help distinguishes source coordinates from arrival directions, mathematical reference curves from emitted light, point from extended sources, and point-mass from SIS/shear models. The source-coordinate legend applies to point/blob figures; the critical-panel exception is tracked above.
  • The final Guide corrects the distinction between surface brightness and total light, explains the critical-panel symbols and the larger-source broken ring, and names the actual point-mode provenance keys. All eight Beat figures and the alternative-command headline checks were regenerated/rechecked from build e30d2c36ae1a on 2026-11-01.

Test Suite Growth

Version 1.2.0: 65 tests; version 1.3.0: 75 tests. Claude’s Audit71 rerun passed all 75 with no skips, including the optional Python 3.10 syntax check. Grok independently checked scientific values but did not rerun the suite because Matplotlib was absent in that review environment. The final documentation pass completed all 75 tests in 7.642 seconds: 74 passed and one skipped because Python 3.10 is not installed on this host. No test failed; the test module is unchanged.

From GFTGUX-Programs/GravitationalLensing/tests/, run python -W error::RuntimeWarning -m unittest test_physics_gl -v with MPLBACKEND=Agg for noninteractive verification.

Known Limitations

  • Fixed-distance thin-lens teaching models and schematic rays are retained; finite grids limit morphology, and image counts inside the documented near-caustic buffer are not promised.
  • True point-source alignment has divergent magnification; rounded signed magnifications cannot retain a unit sum residual at arbitrarily large finite values.
  • Automatic grids stop at 401 pixels; the usable lens-mass range depends on mode, field and source width.
  • Native Windows/macOS interactive GUI behavior was not tested in this documentation pass; figure generation used Agg.

Known Minor Maintenance Items

  • Help-only editorial observations remain: the EXP-8 Beat cross-reference, EXP-10’s missing save option, ambiguous “diagonal” wording, source-shape versus lens parameters, and the simultaneous source-size/offset change (Claude P4-2–P4-6).
  • The arcs critical curve has no legend; its cyan/red correspondence is explained in the Guide (Claude P4-7). The build gives no console save-path summary, and the schematic rays height label gives no unit (P4-8–P4-9).
  • Some shared CLI options are irrelevant to particular modes; rays ignores --beta_x. Point-mode Einstein-angle provenance uses theta_e_arcsec; the optional Audit71 suggestion naming theta_e_rad does not describe that mode’s key.
  • --interactive remains accepted although display is already normal behavior. The optional Python 3.10 check requires that interpreter.

Version: 1.0.1; Build: ba265665c298; Date: 2026-09-11

Release Status

Version 1.0.1 is a targeted patch to 1.0.0, made directly at the maintainer's request after Claude's Audit2 review of the 1.0.0 Response artifacts identified a minimum-Python-version defect. It is not a further round of the Codex/Copilot audit cycle recorded for 1.0.0; it corrects a single, narrowly scoped bug in that release. No thin-lens physics, no plotted data, and no CLI behavior changed. Existing 1.0.0 sample outputs remain numerically valid; they were regenerated for this release only to update the version/build stamp burned into each figure's footer and provenance sidecar.

Bug Fixed
  • Minimum Python version violated. The Help file and 1.0.0 Release Notes document a minimum requirement of Python 3.10, but plot_gl.py contained three provenance-dict field expressions of the form f"{... \n ...}" — an f-string whose replacement-field expression was split across a physical line break. That construct is legal only under the relaxed f-string grammar introduced by PEP 701 in Python 3.12, so it raised SyntaxError at import time on Python 3.10 and 3.11, the two versions the documentation names as supported minimums. The three sites were in plot_point, plot_arcs, and plot_kappa, all in the fov_arcsec field of the saved provenance metadata.
  • Fix. In each of the three functions, the field of view difference is now computed once into a local variable (ext = _extent_arcsec(theta_x, theta_y)) before the provenance dictionary is built, and the dictionary uses the single-line expression f"{ext[1] - ext[0]:.4f}". The computed value, and every other field written to the provenance sidecar, is unchanged from 1.0.0.
  • Regression test added. tests/test_physics_gl.py gained TestMinimumPythonVersionCompatibility, which shells out to a python3.10 interpreter (when one is available on the test host; the check is skipped, not failed, if it is not installed) and confirms that physics_gl.py, driver_gl.py, plot_gl.py, and main.py all still parse under ast.parse with that interpreter's grammar. This guards against the same class of syntax regression reappearing in a future edit.
What Did Not Change
  • All thin-lens physics, the point-mass and SIS+shear formulas, the sampling and field-of-view contracts, and the seven teaching modes are identical to 1.0.0.
  • No numeric output of any mode changed. The seven sample-output figures shipped with this release are regenerated only so their footer text and provenance sidecars report 1.0.1 / ba265665c298 instead of 1.0.0 / e1f4ab42a813; the underlying data plotted is the same as 1.0.0 within ordinary run-to-run floating-point reproducibility.
  • The Known Limitations and Known Minor Maintenance Items recorded in the 1.0.0 notes still apply and are not repeated here.
Test Suite

The release suite now contains 56 tests (the 55 tests carried over from 1.0.0, plus the new minimum-version regression test). All 56 pass under MPLBACKEND=Agg from GravitationalLensing/ using a Python 3.11 interpreter. Because the syntax defect this release fixes prevented the modules from even being imported on Python 3.10/3.11, that failure could not previously have been caught by a runtime test on an affected interpreter; the new test instead parses the source directly with ast.parse, which does not require the module to be importable or require any third-party dependency to be installed.
