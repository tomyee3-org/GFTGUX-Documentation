GravitationalLensing 1.2.0 Release Notes

Version: 1.2.0; Build: 6e3701cf4641; Date: 2026-10-26.

Release Status

This Pre-Pre-Kickoff7 maintenance package makes source-position defaults uniform before review of the merged Help file. The preceding 1.1.0 code round has Claude's Audit41 APPROVE recommendation recorded below. No independent auditor has reviewed this 1.2.0 change or the current Help merger; the Pre-Kickoff7 review has not begun.

Open Bugs

No unresolved reviewer-reported P1–P3 defect is recorded in the supplied release history. This focused maintenance check does not constitute a scientific or instructional review of the merged Help.

Major Improvements in This Release

  • --beta_x and --beta_y now default to zero in every mode. Supplying only one coordinate leaves the other at zero. Direct Python driver calls use the same defaults.
  • The mode-dependent default resolver and the separate rays fallback were removed. A bare point-mode run now shows the centered-source ring. A bare rays run shows an on-axis source in both panels; pass --beta_y 0.35 for the off-axis comparison.
  • The current Help states the common defaults. Worked commands explicitly supply source coordinates, including the ray comparison and the nonzero source required for EXP-8's finite magnifications.
  • All eight SampleOutputs figures were regenerated from this build. The guide specifies the positions used and follows the current merged Help's blob example at (0.15, 0) arcsec.

Test Suite Growth

The supplied suite has 62 tests; 1.2.0 has 65. All 65 completed, with 64 passing and one skipped because Python 3.10 is not installed on the check host. From GFTGUX-Programs/GravitationalLensing/tests/, run python -W error::RuntimeWarning -m unittest test_physics_gl -v with MPLBACKEND=Agg. New tests cover omitted, partial, explicit-zero and signed nonzero coordinates in every CLI mode, the no-option default, and EXP-8's source and magnifications. Existing actual driver runs now verify zero-source provenance. All 33 documented command forms also completed successfully under Agg with RuntimeWarnings treated as errors.

Known Limitations

  • The lenses and distances are fixed teaching models; rays are schematic and intensity maps use false colour. Near-caustic image counts and finite-grid morphology retain their documented limits.
  • The rays side view uses only --beta_y; --beta_x has no effect. Neither source coordinate affects the source-independent kappa mass map.

Known Minor Maintenance Items

  • Options unrelated to a mode can still be accepted without affecting that mode. The optional Python 3.10 syntax check skips when that interpreter is unavailable.
  • The Help merger awaits its separate Pre-Kickoff7 review. Older 1.0.0 release notes cited in the retained history were not supplied.

Version Identification

MODEL_VERSION: 1.2.0; BUILD_ID: 6e3701cf4641. The identifier hashes only the LF-normalized four core files: physics_gl.py, driver_gl.py, main.py and plot_gl.py, with file-name and length framing. Documentation and tests do not affect it.

Open Bugs

Claude's Audit41 found no open P1–P3 defects in the 1.1.0 candidate. No reviewer-reported P1–P3 issue remains open from the supplied 1.0.1 history.

Major Improvements in This Release

  • Both tutorial formats now share the same four core files, one test suite, and a single sample guide; the suite requires both Help files, checks their matching version/build and validates the worked Beat commands against the real argument parser.
  • Beat 2 now has its own point-mass run with a source at 1.0 arcsec. The point-mode provenance records both signed ideal image positions and magnifications; shear-mode provenance records both cusp axes and the minimum and maximum critical radii.
  • The Extended-style Help corrects the default source cross from “outside” to “inside” the 2.018-arcsec Einstein circle, and narrows the magnification-sum statement to its point-mass scope. The sample guide distinguishes the SIS-plus-shear caustic from the point-mass caustic.
  • Exercises EXP-2, EXP-6 and EXP-8 now specify the total source offset, use separately verified fold and cusp source positions, provide commands that save the needed provenance values, and limit the magnification-sum exercise to the point-mass model. Both tutorial styles show the new fold and cusp comparison commands.
  • The build-only --sync-help option was removed from the student CLI. The maintainer helper still takes an explicit Help path; the guides were stamped separately. This public command-line change warrants the 1.1.0 minor version.
  • The SampleOutputs Guide now embeds eight newly generated figures, one per Beat, and quotes this build's plot/provenance values, including the two unequal cusp distances.

Test Suite Growth

The original 1.0.1 suite contained 56 tests; the shared 1.1.0 suite contains 62, with 61 passing and one skipped on this host because the optional Python 3.10 interpreter is absent. Run once from the program folder: MPLBACKEND=Agg python -W error::RuntimeWarning -m unittest tests.test_physics_gl -q. New coverage includes both tutorial styles, every Beat's runnable commands and numeric point-image positions, the shared guide, the absence of the build-only CLI flag, and the new point-image and shear-cusp provenance.

Known Limitations

  • The lens plane and distances are fixed teaching choices: there is no evolving cosmology, multicomponent mass model or geodesic integration. Rays are a schematic side view and rendered intensities are false colour.
  • Near a fold or cusp the Newton image solver does not promise a stable count within the documented buffer; source widths and pixel resolution limit visible image morphology.
  • The SIS is singular at its centre and uses a softened sampling pixel for its convergence map. Its pseudo-caustic and image-count changes are properties of this idealized lens.

Known Minor Maintenance Items

  • Options belonging to other modes can be accepted without affecting a run. Mode-specific option checks and more explicit output remain candidates for a later round.
  • The separate Python 3.10 syntax check skips when that interpreter is unavailable. Continuous integration should provide it to guarantee the documented minimum.
  • The older 1.0.0 notes referenced by the retained 1.0.1 history were not included in the supplied archives.

Version: 1.0.1; Build: ba265665c298; Date: 2026-09-11

Release Status

Version 1.0.1 is a targeted patch to 1.0.0, made directly at the maintainer's request after Claude's Audit2 review of the 1.0.0 Response artifacts identified a minimum-Python-version defect. It is not a further round of the Codex/Copilot audit cycle recorded for 1.0.0; it corrects a single, narrowly scoped bug in that release. No thin-lens physics, no plotted data, and no CLI behavior changed. Existing 1.0.0 sample outputs remain numerically valid; they were regenerated for this release only to update the version/build stamp burned into each figure's footer and provenance sidecar.

Bug Fixed
  • Minimum Python version violated. The Help file and 1.0.0 Release Notes document a minimum requirement of Python 3.10, but plot_gl.py contained three provenance-dict field expressions of the form f"{... \n ...}" — an f-string whose replacement-field expression was split across a physical line break. That construct is legal only under the relaxed f-string grammar introduced by PEP 701 in Python 3.12, so it raised SyntaxError at import time on Python 3.10 and 3.11, the two versions the documentation names as supported minimums. The three sites were in plot_point, plot_arcs, and plot_kappa, all in the fov_arcsec field of the saved provenance metadata.
  • Fix. In each of the three functions, the field of view difference is now computed once into a local variable (ext = _extent_arcsec(theta_x, theta_y)) before the provenance dictionary is built, and the dictionary uses the single-line expression f"{ext[1] - ext[0]:.4f}". The computed value, and every other field written to the provenance sidecar, is unchanged from 1.0.0.
  • Regression test added. tests/test_physics_gl.py gained TestMinimumPythonVersionCompatibility, which shells out to a python3.10 interpreter (when one is available on the test host; the check is skipped, not failed, if it is not installed) and confirms that physics_gl.py, driver_gl.py, plot_gl.py, and main.py all still parse under ast.parse with that interpreter's grammar. This guards against the same class of syntax regression reappearing in a future edit.
What Did Not Change
  • All thin-lens physics, the point-mass and SIS+shear formulas, the sampling and field-of-view contracts, and the seven teaching modes are identical to 1.0.0.
  • No numeric output of any mode changed. The seven sample-output figures shipped with this release are regenerated only so their footer text and provenance sidecars report 1.0.1 / ba265665c298 instead of 1.0.0 / e1f4ab42a813; the underlying data plotted is the same as 1.0.0 within ordinary run-to-run floating-point reproducibility.
  • The Known Limitations and Known Minor Maintenance Items recorded in the 1.0.0 notes still apply and are not repeated here.
Test Suite

The release suite now contains 56 tests (the 55 tests carried over from 1.0.0, plus the new minimum-version regression test). All 56 pass under MPLBACKEND=Agg from GravitationalLensing/ using a Python 3.11 interpreter. Because the syntax defect this release fixes prevented the modules from even being imported on Python 3.10/3.11, that failure could not previously have been caught by a runtime test on an affected interpreter; the new test instead parses the source directly with ast.parse, which does not require the module to be importable or require any third-party dependency to be installed.
