Major Improvements in This Release

  • The relativistic polytrope sequence now uses a tighter surface-density threshold and checks the maximum-mass radius against a further two-decade tightening. Its summary prints the threshold and measured radius drift, and warns when the drift remains material. This changes radius values for cutoff-sensitive parameter choices while leaving the default example essentially unchanged (KB-1).
  • When there is no resolved interior turning point, the causality check covers all converged sampled models and names that scope in the printed summary and warnings. A previously missed acausal high-density sequence is flagged (KB-2).
  • The public turn-off interpolation validates paired masses and lifetimes, while retaining missing lifetime sentinels for unfinished tracks (KB-3).
  • Both tutorial Help styles now describe the low-index polytrope's falling mass, the new surface-cutoff check and the scope of the sound-speed test (KB-4). The mass–radius plot legend no longer covers the maximum-mass marker (KB-5).
  • One shared suite requires both Help files and checks their commands and scientific identity. The SampleOutputs guide contains eleven new embedded images, one for each Beat, regenerated from this build.

Test Suite Growth

The suite grew from 309 tests in 1.7.0 to 315 tests in 1.8.0. Run it from the program folder with MPLBACKEND=Agg python -W error::RuntimeWarning -m unittest tests.test_physics_sev -q. The full suite passed after the revised Beat 9 output assertion was updated. The new cases cover the surface-radius check, provisional-branch causality, turn-off validation and Grok tutorial compatibility; both Help files are required.

Known Limitations

  • These are teaching models and simplified equations of state; no research-grade stellar evolution or realistic neutron-star equation of state is claimed. The four modes are separate model calculations.
  • A reported relativistic turning point must be an interior sampled maximum; it is not refined between grid points. Newtonian sequences have no assigned radial-stability classification.
  • The finite polytrope surface cutoff remains a numerical approximation. The measured radius drift at the selected peak checks one model and one two-decade tightening; it does not certify every sampled radius or parameter choice.
  • The schematic helium-white-dwarf remnant is a mass-based heuristic. White-dwarf Mestel cooling uses the envelope electron weight and excludes several physical cooling mechanisms.
  • Output collision avoidance is confined to a process; offline browsers may display MathJax equations in raw TeX.

Known Minor Maintenance Items

  • Some plot panels lack complete visual regression checks; extreme HR plot masses may clip the zero-age line.
  • The isochrone/turn-off status categories have no machine-readable taxonomy; build_hr_grid() validates some inputs during integration instead of all at entry.
  • The HR workload cap counts post-main-sequence points even when the run disables that stage. Neutron-gas mode silently ignores polytrope-only options.
  • Some private helper docstrings refer to older audit IDs. A deliberately small figure produces a Matplotlib UserWarning; the suite promotes only RuntimeWarning to an error.

The cutoff is not exposed through ns_mass_radius_curve() or the command line, and the program reports no warning for Γ of 1.4 or above. In the reproduction below the mass changes by 0.006%. Reproduction:

Known Limitations

By design, or accepted and documented. These are not defects.

  • Intended for education and conceptual exploration, not research-grade modeling. Every mode is a simplified teaching model: homology relations and empirical closures for the stars; idealized zero-temperature or ideal-gas equations of state for white dwarfs and neutron stars; no rotation, magnetic fields, mass loss, convective overshoot or binary interaction. The four modes are separate models, not one continuous evolution.
  • The schematic low-mass “helium white dwarf” remnant is a single-star, mass-only heuristic. The Help has said so since 1.6.0.
  • The ideal neutron gas (--eos neutron) reaches a maximum of about 0.71 M☉ (0.7100 in 1.7.0) by design. The stiff polytrope is a toy stand-in for nuclear repulsion, not a fit to nuclear matter or observations.
  • Turning-point detection requires an interior sampled maximum and does not refine between grid points; the maximum mass is only as precise as the grid. Since 1.6.0 only TOV sequences get a turning point; Newtonian sequences report a “largest sampled mass” and are not stability-classified (the field name M_max is kept).
  • No comparison with a published white-dwarf mass–radius table. Partly addressed in 1.7.0 by independent oracle tests and a Sirius B check.
  • The Mestel cooling matching layer uses the envelope’s μe. The alternative (core value) would make the coefficient 14.2 times smaller and the default cooling age 79.8 Gyr instead of 5.6235 Gyr. The convention is stated in the Help and tested. The public option is still named --mu_e (Codex A22 asked for a rename; not done; Codex Audit23 accepted the convention).
  • White-dwarf integration is second order in step_frac, and the default step is coarse above about 1e15 kg/m³ (stated in Beat 6).
  • Chandrasekhar-limit coefficient derived in 1.7.0 (5.836 → 5.8252): MCh(μe = 2) is now 1.4563 M☉, not 1.459. The cutoff at 0.999 MCh is 1.4548 M☉, so a white-dwarf mass of 1.455 is now refused.
  • Output-collision protection (CSV, PNG, provenance sidecars) works within one process only; there is no cross-process atomic exclusive create.
  • Scientific narrative is duplicated across the terminal output, CSV/PNG provenance and the Help rather than centralized. Since 1.7.0 the synchronization tests (TestHelpClaimsAgreeAcrossLayers, 12 tests) guard it.
  • The Help loads MathJax from a public CDN; offline, the TeX is shown untypeset. The program itself needs no network.
  • Kickoff2 shipped no .py.txt transport companions, so the earlier limitation about them no longer applies.

Known Minor Maintenance Items

  • A three-way isochrone/turn-off status taxonomy (outside the mass grid; inside the grid but time-truncated; too few surviving points) is not implemented as machine-readable states; the two symptoms it would address are fixed and explained in text.
  • The boolean-type-checking sweep covers the public API (45 entry points, 408 cases, done in 1.7.0); private helpers are not swept. Numeric strings are still coerced by float() (PolytropeEOS(gamma="2.5") works); booleans are refused.
  • build_hr_grid() does not pre-validate every mass before integrating; the command line does. A direct call fails later with a clear error.
  • The HR-mode workload cap counts n_post even under --no_postms. It errs on the safe side.
  • --eos neutron silently ignores --gamma and --p_nuc, and the CSV lists them as “default”.
  • Numerical-methods refinements to the integrators (intermediate-state clamping near a white-dwarf surface; linear rather than event-detected interpolation at the TAMS crossing and the cooling-track endpoint) remain candidates for a dedicated round.
  • Plot regression tests are structurally partial; not every panel of every mode is covered.
  • HR-plot ZAMS line may clip at extreme masses, and the Sun marker is not labelled as an external reference (declined as polish).
  • Kramers-opacity validity warnings at extreme compositions (X = 0, Z = 1) were declined; off the documented path.
  • Three private-helper docstrings (_require_nonneg_x, _unique_stem, _finish) still cite Audit3 reviewer IDs. Moving them would change BUILD_ID with no behaviour change.
  • One test emits a Matplotlib UserWarning for a deliberately tiny figure; the suite promotes only RuntimeWarning to an error.
  • Beat 2 keeps six commands together by design; splitting would renumber every beat, pointer and test.
  • Outside the release: the repository copy of package/transport_codec.py has a leading-space IndentationError (Kickoff2 finding F2).
  • Retired: “duplicate isochrone ages are not rejected” (listed in 1.5.0). Duplicate ages have been rejected since 1.3.0; the Help documents it since 1.6.0.
