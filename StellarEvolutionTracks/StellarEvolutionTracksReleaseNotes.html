Release Status

Version 1.5.0 concludes a kickoff regression-suite build followed by four rounds of independent review involving Claude, Codex, Copilot, and Gemini. The reviewers checked the stellar-evolution track, HR-diagram, white-dwarf cooling, and neutron-star mass–radius modes against their stated governing equations (homology relations and burning-law ODEs on the main sequence; core-mass–luminosity and Hayashi-line closures post-main-sequence; the exact Fermi-gas equation of state and Chandrasekhar structure for white dwarfs; the Tolman–Oppenheimer–Volkoff and Newtonian structure equations for neutron stars); verified remnant classification consistency across every output layer, numerical safeguards and input validation, output provenance and reproducibility, Help-file accuracy, Version/Build synchronization, and regression coverage; and tested both the canonical and flattened upload layouts. No release-blocking defect remains. Copilot and Gemini both recommended release after the Audit4 round with only previously disclosed, low-severity observations outstanding; Codex's one remaining reproducibility gap and three hardening items from that same round are fixed in this release, closing it with no open findings from any reviewer. The program is sufficiently robust, accurate, and clear for student use within the tutorial scope and limitations described below.

Major Improvements in This Release

  • Fixed a one-sided neutron-star turning-point check that could report a stable maximum mass from a sequence sampled entirely on one side of the true (unsampled) turning point; the check now requires an interior maximum on both sides, with distinct, actionable warnings for each one-sided failure.
  • Fixed two related remnant-classification contradictions: a low-mass track's schematic outcome could disagree with what its own post-main-sequence integration actually computed, and "reached helium ignition" was being read from the wrong flag. A new remnant_basis field now threads a single, consistent story ("this track's own computed endpoint" versus "mass-only schematic classification") through the terminal summary, CSV comments, and plot annotations.
  • Fixed a core-mass discontinuity at the main-sequence/post-main-sequence boundary for non-default --x_end values, so the post-main-sequence phase now begins continuously from the star's own last main-sequence state.
  • Made wd_structure() raise an explicit, actionable error when its bisection search fails to converge, instead of silently returning an unconverged mass–radius pair; the search bracket now also widens adaptively so masses legitimately close to the Chandrasekhar limit succeed, and bracket-failure guidance is now side-specific (a too-small target mass gets different advice than one too close to the limit).
  • Replaced the closed-form Fermi-gas pressure and energy-density expressions' small-x catastrophic-cancellation region with an exact Taylor-series branch, and added a validator (_require_nonneg_x) so all six public FermiGasEOS evaluators now reject negative, non-finite, boolean, or complex input with a clean, consistent error instead of returning silently wrong numbers or leaking a raw TypeError.
  • Every saved PNG now has a same-stem .provenance.txt sidecar, written unconditionally, recording the code version/build, the rendering settings (dpi, line width, and figure size in inches), and—for an ordinary run through the program—every mode-specific scientific parameter used, so a saved figure is independently reproducible without also requesting a CSV. Collision handling protects both the PNG and its sidecar, including a pre-existing orphaned sidecar left by an earlier run.
  • Added systematic input validation across the physics and driver layers: bisection tolerances and iteration limits, structure-integration seed values and step controls, composition and mass-range checks, isochrone-count and aggregate HR-mode workload caps, and boolean-parameter type checks, each closing a specific reproducible gap rather than a blanket sweep.
  • Corrected several Help-file overstatements and inaccuracies: a false claim about neutron-star mass measurements, "exact" wording that blurred the line between an exact governing equation and an approximate numerical solution, an outdated description of which ODEs are actually integrated on the main sequence, and missing piecewise ZAMS anchor formulas.
  • Modernized physical constants to current CODATA 2022 values and derived the solar mass from the IAU-nominal GM☉ parameter so it can never drift out of consistency with the module's own G; corrected the YEAR constant to the Julian year its own comment claimed; replaced duplicated Earth-radius literals with one named, sourced constant.
  • Same-second output collisions (CSV, PNG, and their sidecars) are now detected and disambiguated within a single run rather than silently overwritten.
  • Introduced a collision-free, self-escaping transport-encoding scheme for the .py.txt companion files generated alongside each delivered .py source, solving a recurring Markdown-rendering corruption problem in one reviewer's environment; the scheme is verified byte-for-byte against an adversarial test corpus before every delivery.

Test Suite Growth

A new 158-test regression suite was created at kickoff and expanded to 210 automated tests across four rounds of audit-driven hardening (158 → 184 → 197 → 207 → 210). The suite defines the program's four core module filenames and locates them from either the canonical tests/ directory or an upload layout flattened beside the program modules, so the same test file works in both. The full suite is run exactly once per delivery from the canonical layout, with RuntimeWarning promoted to an error; the flattened layout is checked separately with a deliberately trivial import-and-one-fact smoke test, never a second full run.

The final suite verifies physical constants and their sourcing; composition and mean-molecular-weight formulas; ZAMS anchor continuity and monotonicity; main-sequence and post-main-sequence track integration, including phase transitions, core-mass continuity, and remnant-classification consistency; the exact and small-x-series Fermi-gas equation of state, including boundary, negative, non-finite, boolean, and complex-input rejection; white-dwarf structure and Mestel cooling, including bracket-failure behavior in both directions; neutron-star structure under both Newtonian and TOV gravity, including turning-point detection and failed-model handling; CSV and PNG output correctness, provenance-sidecar content and collision handling across every mode; command-line execution; Help-file structure and scientific content, cross-checked against the running code; and independent reproduction of the BUILD_ID hash. All 210 tests pass under this environment's CPython 3.11 in both the canonical and flattened layouts.

Known Limitations

  • Intended for education and conceptual exploration of stellar-evolution and compact-object physics, not research-grade stellar modeling. Every mode is a deliberately simplified teaching model: main-sequence and post-main-sequence evolution use homology relations and empirical closures rather than a full stellar-structure integration; white-dwarf and neutron-star structure use idealized zero-temperature or ideal-gas equations of state; rotation, magnetic fields, mass loss, convective overshoot, and binary interaction are not modeled.
  • The schematic low-mass "helium white dwarf" remnant classification is a single-star mass-only heuristic; real helium white dwarfs at these masses generally require binary mass stripping to form, which this program does not simulate.
  • The ideal degenerate neutron-gas equation of state (--eos neutron) supports at most about 0.7 solar masses—well under the roughly 1.4–2 solar masses of a typical measured neutron star—by design, so students can see degeneracy pressure alone is insufficient; the stiff-polytrope option is an illustrative stand-in for nuclear repulsion, normalized for pedagogical resemblance, not a fit to microscopic nuclear matter or observations.
  • Turning-point detection in the neutron-star mass–radius sequence requires an interior sampled maximum; it does not perform local slope-sign-change refinement or interpolation, so the reported maximum mass is only as precise as the sampling grid.
  • No independent, externally published white-dwarf mass–radius benchmark comparison is included. Internal consistency checks (the Chandrasekhar-mass asymptote, non-relativistic scaling laws) are extensive, but this remains a validation opportunity rather than a demonstrated defect.
  • Same-second output-collision protection (CSV, PNG, and their provenance sidecars) is deterministic and effective within one running program, but there is no stronger cross-process atomic-exclusive-create guarantee against two independent processes racing to create the same filename; no exercise in this program depends on concurrent processes sharing an output directory.
  • Scientific-model narrative (remnant-basis wording, provenance phrasing) is intentionally worded consistently but duplicated across several consumer layers (terminal output, CSV/PNG provenance, the Help file) rather than centralized in one shared template, which aids transparency and auditability at some future maintenance risk if one layer is edited without the others.
  • The .py.txt transport-encoded companion files shipped alongside each delivered source file are a packaging aid only, meant to survive Markdown-oriented rendering pipelines during review; they are never meant to be executed and are not part of the program.
  • The Help file loads MathJax from a public CDN. Offline, its prose and unrendered TeX source remain available, but equations are not typeset; this has no effect on the program itself, which needs no internet access to run.

Known Minor Maintenance Items

  • A full three-way isochrone/turn-off status taxonomy (outside the mass grid; inside the mass grid but time-truncated; insufficient surviving points) is not implemented as separate machine-readable states; the two concrete symptoms this would address—silent zero-isochrone omission and misattributed turn-off wording—are both fixed and explained in plain text.
  • An exhaustive boolean-type-checking sweep of every low-traffic internal helper was not performed; the module's most-used boolean-like public parameters are covered.
  • build_hr_grid() does not pre-validate every mass in a list before starting expensive integration work; an invalid mass anywhere in the list still fails with a clear error from inside track integration, just not always as early as possible.
  • Isochrone lists are not rejected for duplicate ages the way duplicate masses already are; a duplicate age still produces correct, merely redundant, output.
  • Minor numerical-methods refinements to already-convergence-tested integrators (intermediate-state clamping near a white-dwarf surface, linear versus event-detected endpoint interpolation at the TAMS crossing and the cooling-track endpoint) remain candidates for a dedicated numerical-methods round rather than this maintenance track.
  • Plot regression tests assert several structural properties (axis direction, marker/annotation gating, output-file pairing) but do not yet form a comprehensive structural test pass across every panel of every mode.
