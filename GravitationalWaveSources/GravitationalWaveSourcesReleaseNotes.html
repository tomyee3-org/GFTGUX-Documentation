GravitationalWaveSources 1.7.0 Release Notes

Version: 1.7.0
Build: 54e086464f39
Date: 2026-09-01

Release Status

Version 1.7.0 concludes a kickoff review followed by eight rounds of independent review involving Codex, Copilot, and Gemini. The reviewers verified the leading-order quadrupole inspiral physics, the RK4 numerical integrator and its convergence behavior, the illustrative Schwarzschild ringdown model, the physical-constants policy, atomic and secure CSV/PNG publication, input validation, plotting, Help-file accuracy, Version/Build synchronization, and regression coverage; and exercised both the canonical and flattened upload layouts. Copilot and Gemini both recommend immediate release after Audit 8, with no release-blocking defect identified in either review. Codex's Audit 8 review recommends against release, citing one substantive finding (resource-lifetime and diagnostic completeness in the permission-probe cleanup path added at Audit 6) and two minor documentation/diagnostic-channel findings -- all three are software-stability and polish issues in a narrow, low-probability code path, not defects in the physics engine, the published numerical results, or any student-facing scientific content. The program's author has reviewed Codex's findings, agrees they do not rise to release-blocking severity for an instructional program used in ordinary single-user, locally-trusted directories, and has approved release of 1.7.0 with all three items tracked below as Known Minor Maintenance Items for a future maintenance round.

Major Improvements in This Release

  • Coupled ringdown sampling to the QNM frequency so --rd_pts must resolve at least 8 samples per oscillation cycle relative to --n_tau, rejecting settings that previously produced a silently aliased or invisible ringdown waveform instead of a misleading plot.
  • Added chirp_mass_from_fdot(), the observational inverse of the chirp-mass relation (deriving Mc from a measured frequency and its time derivative, matching the real gravitational-wave-detection analysis formula), with log-domain evaluation so extreme inputs return correct tiny or huge finite results instead of silently underflowing or overflowing.
  • Exposed the model's internal phase array and validated it against an independently-derived closed-form phase oracle, coded from scratch rather than reusing any of the RK4/dfdt machinery being tested, closing a previously tautological self-consistency check.
  • Adopted the IAU 2015 Resolution B3 nominal solar-mass parameter as this program's basis for M_sun, a deliberate author policy decision (this experimental program is not bound to reproduce a legacy published value the way a direct port of existing textbook code would be); M_sun is now stored as the unrounded quotient GM_sun_nominal / G rather than a separately-rounded literal, so G × M_sun reproduces the nominal parameter to full floating-point precision, and an independent regression test verifies this against a second, independently-copied reference value.
  • Corrected an inaccurate code comment that had claimed a single, unqualified "sub-milliradian" final-step interpolation error; the true error is case-dependent and is now reported as a measured figure for each documented reference case, not assumed.
  • Redesigned artifact publication end to end: CSV/PNG content is written through a securely-created, randomly-named private temporary file's own file descriptor (never reopened by path), its identity is re-verified against the filesystem immediately before publication, and the public file is created only once, atomically, via os.link() -- eliminating both a visible zero-byte public file during writes and the symlink-substitution attack surface a predictable or reopened temp path would allow.
  • Normalized published CSV/PNG file permissions to the ordinary umask-controlled mode a plain file save would produce, rather than silently inheriting the private temporary file's restrictive mode (which would have made every export unreadable to anyone but the user who ran the program on a shared machine); the permission-discovery mechanism itself never reads or mutates the process-wide umask, instead letting the kernel apply it atomically during a real, disposable probe-file creation -- closing a process-wide race a simpler read-the-umask-by-toggling-it approach would have introduced.
  • Output directories (--outdir/--csvdir) are validated and created before any artifact write begins, so a bad output path is caught before a CSV is written rather than leaving a completed CSV next to a failed PNG.
  • Added explicit, prominently-placed Help-file language disclosing that CSV/PNG output directories must be under the student's own control and not writable by an untrusted co-tenant process, and that this program's publication-atomicity guarantees are scoped to that ordinary, non-adversarial case.
  • Rejects bool/numpy.bool_ values across every numeric parameter rather than silently coercing them to 1.0/0.0, and converts overflow from extreme numeric-string inputs (e.g. a 400-plus-digit --dpi or a subnormal --dt) into a clean, descriptive error at every layer instead of a raw traceback.
  • Added an explicit upper bound on --dpi and moved ringdown/QNM validation to run immediately after total mass is known, before the (potentially expensive) inspiral integration, so invalid ringdown settings on a large run are rejected in a fraction of a second rather than after the run completes.
  • Added a self-documenting --csvdir CSV export with a commented metadata preamble recording the model version, build identifier, UTC export timestamp, and every parameter that affects the exported waveform.
  • Added an in-plot ringdown annotation ("illustrative ringdown -- not a physical merger") so the caveat is visible on the saved PNG itself, not only in accompanying Help text.
  • Rewrote the RK4 fourth-order convergence regression to compare against an algebraically exact closed-form solution of the governing frequency ODE, derived and coded independently of the stepper under test, eliminating a fragile numerical-vs-numerical comparison that had required repeated retuning as physical constants changed by fractions of a floating-point unit.
  • Cached the program's expensive default (~789,000-step) reference integration across the handful of tests that genuinely need that exact case, cutting full-suite runtime substantially, and made the cached NumPy result arrays read-only so an accidental in-place mutation by one test raises immediately rather than silently corrupting a later test that shares the same cached object.
  • Removed round-by-round audit-history commentary from the three student-facing implementation modules (physics_gw.py, driver_gw.py, plot_gw.py), leaving only permanent, present-tense design rationale, per the program author's explicit direction that these files are primary student reading material; the regression test suite's audit-trail comments were deliberately retained at the author's explicit confirmation, since they document why each individual regression exists for future maintainers.
  • Added a reproducible BUILD_ID computed across the four executable source modules, independent of CRLF-versus-LF line-ending differences, that self-reports as "unknown" rather than failing outright if the source cannot be located or decoded (as can happen in a frozen or relocated distribution), and stays synchronized across source, Help file, and runtime output.
  • Added an explicit "Requires Python 3.10+" statement to the program and Help file, and verified the full regression suite passes from both the canonical tests/ layout and a flattened upload layout.

Test Suite Growth

A regression suite was built from zero at kickoff (92 tests) and grew steadily through every review round -- 124, 141, 156, and 160 tests across Audits 1 through 4, then 164, 169, 173, and (unchanged) 173 tests across Audits 5 through 8 -- reaching 173 automated tests for this release. The suite defines the program's four core module filenames and locates the nearest directory containing all four, so the identical test file runs unmodified from the canonical tests/ directory or a flattened upload layout.

The final suite independently re-derives every physical formula the program uses (chirp mass, ISCO frequency, strain amplitude, inspiral time, QNM ringdown parameters, and now an exact closed-form frequency-versus-time solution) from raw physical constants copied separately from the program's own, specifically so a bug in the program's own derivation cannot be silently "confirmed" by a test sharing the same buggy value; verifies RK4 stepper order and convergence, input validation across every parameter and its boundary/overflow cases, atomic and collision-safe CSV/PNG publication under injected filesystem failures (including symlink-substitution and permission-probe-cleanup-failure scenarios), umask-derived file permissions and their thread-safety under concurrent export calls, full CLI subprocess execution, and Help-file structural and scientific-content accuracy against the program's own live parameter defaults. All 173 tests pass in one run of MPLBACKEND=Agg PYTHONWARNINGS=error::RuntimeWarning python test_physics_gw.py from within tests/, with RuntimeWarning promoted to an error.

Known Limitations

  • Intended for education and conceptual exploration of leading-order quadrupole gravitational-wave physics, not as a precision template-generation or research-grade data-analysis pipeline.
  • Publication of the public CSV/PNG filename still relies on a pathname-based os.link() call after the private temporary file's identity has already been re-verified; a process with write access to the same output directory that is actively racing this program could still substitute a different file in the narrow window between that check and publication. This is disclosed explicitly in the Help file and is an accepted boundary of the program's documented single-user, trusted-directory threat model, not an eliminated defect -- do not point --csvdir/--outdir at a directory writable by users or processes you do not trust.
  • Atomic publication relies on ordinary local-filesystem hard-link support; on a filesystem or mounted network share that does not support creating hard links, publication fails outright with an explanatory error rather than falling back to a weaker save strategy.
  • The reported "time to ISCO" is limited by a single linear interpolation at the final RK4 step (a pedagogical cutoff, not a root-solved event finder), so it does not show the stepper's true fourth-order convergence rate as --dt is refined; a convergence study should instead compare a quantity sampled well before the cutoff, as the Help file's numerical-convergence exercise now does.
  • The amplitude envelope is defined only for the inspiral and is undefined (NaN) during the illustrative ringdown segment, which is explicitly labeled -- in both the Help file and directly on the saved plot -- as an illustrative Schwarzschild quasi-normal-mode model, not a physical merger.
  • The six low-level physics equation helpers (chirp mass, df/dt, strain amplitude, ISCO frequency, QNM parameters, inspiral time) are intentionally unvalidated for out-of-domain inputs; all validation happens once, up front, in integrate_inspiral(), since several of these helpers run millions of times inside a single integration and per-call validation at that scale is not free.
  • The Help file loads MathJax from a public CDN; offline, its prose and unrendered TeX source remain readable, but equations are not typeset.
  • The secure-publication helper functions are deliberately duplicated between driver_gw.py and plot_gw.py rather than factored into shared code, per this project's standing convention of not sharing code across that module split -- an acknowledged maintenance cost, not an oversight.

Known Minor Maintenance Items

  • The permission-probe cleanup path added at Audit 6 (_default_output_file_mode() in both driver_gw.py and plot_gw.py) attempts to close and then remove a disposable, empty temporary file; if the close operation itself fails, the exception is currently discarded without any diagnostic (unlike the parallel case of a failed removal, which does print a warning), and in that rare case the underlying file descriptor may remain open for the life of the process. The two regression tests added to exercise this path mock the close call away entirely and so do not themselves close the real descriptor, leaving two descriptors open for the life of a full test-suite run. Codex's Audit 8 review identified this precisely and recommends either propagating the close failure after the unlink attempt or emitting an explicit close-failure diagnostic, plus repairing both tests to close the real descriptor they intentionally prevent production code from closing. Tracked for the next maintenance round.
  • The diagnostic warning printed when the disposable permission-probe file's own removal fails is written to standard output rather than standard error, so it cannot currently be distinguished from the ordinary run-summary/save-status stream by a caller that redirects or captures the two channels separately. Tracked for the next maintenance round, alongside the item above.
  • The Help file's disclosure of the .gw_modeprobe_* temporary-file debris pattern is attached only to the CSV output row's description, even though it can equally arise from a PNG-only (--outdir-only) run; a student who saves only a PNG currently has no textual pointer, next to the PNG row, to that explanation. Tracked for the next maintenance round.
  • The regression test suite has grown past 3,000 lines in a single file; splitting it into thematic modules remains deferred as an informational-only maintainability concern, to avoid destabilizing the flattened-upload-layout module-discovery mechanism in the same round as other changes.
  • The secure-publication helpers' duplication between driver_gw.py and plot_gw.py (see Known Limitations above) has, on multiple occasions during this project's review history, meant a defect found in one module's implementation was present verbatim in the other's and had to be fixed and independently re-verified in both places rather than once; a shared private implementation utility, or at minimum a contract-test mixin applied identically to both copies, remains a reasonable future simplification if this project's four-module teaching architecture is ever revisited.
