Release Status

Version 1.4.0 concludes a kickoff regression-suite build followed by four rounds of independent review involving Claude, Codex, Copilot, and Gemini. The reviewers verified the Schwarzschild null-geodesic equations of motion against an independently re-derived first integral and potential-maximization argument; the event-horizon, photon-sphere, and critical-impact-parameter closed forms; the fourth-order Runge–Kutta integration and its linear event-location interpolation; input validation and extreme-value/floating-point behavior; scale invariance; plotting, output-file collision avoidance, and provenance/reproducibility; Help-file scientific and pedagogical accuracy; Version/Build synchronization; and regression coverage in both the canonical and flattened upload layouts. No release-blocking defect remains. Copilot and Gemini both report no functional concern in the final review round, and Gemini states the codebase is structurally complete and ready for Prof. Schutz to evaluate for the second edition of Gravity from the Ground Up. The program is sufficiently robust, accurate, and clear for student use within the tutorial scope and limitations described below.

Major Improvements in This Release

  • Independently re-derived and verified the governing physics — the radial first integral (dr/dλ)² = E² − (L²/r²)(1−2M/r), the radial acceleration d²r/dλ² = (L²/r³)(1−3M/r), the angular equation dφ/dλ = L/r², and the event horizon, photon sphere, and critical impact parameter at 2M, 3M, and 3√3 M — against a from-scratch finite-difference cross-check and a potential-maximization argument, and built the program's first regression suite (89 tests) covering the physics, input validation, plotting, output, and Help-file content.
  • Fixed a tangential-launch misclassification: a photon launched exactly at the local kinematic bound for its starting radius (zero initial radial velocity) was not recognized as outward-moving on either side of the photon sphere, due to a negative-zero sign comparison. Fixed by testing the current-step velocity directly, and confirmed correct on both sides of the photon sphere and at the exact circular orbit.
  • Event-located horizon and escape-radius crossings via linear interpolation within the final integration step, replacing a whole-step overshoot that had been contaminating the step-size convergence study (EXP-9); Δφ and the final affine parameter now converge cleanly as the step size shrinks.
  • Hardened the physics layer against extreme-but-finite inputs — very large or very small GM_over_c2/r0/b/lambda_max, and Python integers too large to convert to a float — so each is rejected with a documented, single-line ValueError instead of a raw OverflowError or ZeroDivisionError. A ratio-first rewrite of the core formulas (dividing by the radius before squaring or cubing it) additionally closed a case where an ordinary, uniformly rescaled trajectory at a very small but physically unremarkable scale failed with a premature division-by-zero.
  • Tightened the local kinematic-bound check at a photon's starting radius to compare the impact parameter directly against a scale-stable bound, rather than gating acceptance on the size of a floating-point rounding residual — closing a band of spuriously accepted, physically forbidden impact-parameter values immediately above the true separatrix.
  • Added a per-saved-run provenance sidecar and a losslessly precise "Reproduce this exact run with:" command, printed to the console and written beside every saved PNG, including the two rendering settings (--dpi, --lw) PhotonOrbit itself controls. Documentation throughout the program and Help file is scoped honestly: the command reproduces the exact physics inputs and PhotonOrbit's own rendering options, not a byte-identical image, since the ambient Matplotlib style and environment are not fixed or recorded.
  • Replaced a check-then-write filename race with an atomic reservation (os.O_CREAT|os.O_EXCL) for saved PNGs, so two runs completed within the same wall-clock second — or two concurrent processes — can never silently overwrite one another's output. Verified with a dedicated multi-thread concurrency regression that exercises the reservation primitive directly.
  • Corrected the Help file's explanation of gravitational light bending (it had stated the wrong direction of approach to the critical impact parameter for captured trajectories, and briefly contradicted itself) and added a clarification distinguishing the reported accumulated azimuth (Δφ) from the conventional asymptotic light-deflection angle, which is undefined for a captured trajectory.
  • Established and enforced a project policy keeping all development/review history out of the four student-facing program modules — they are read directly by students for the governing physics and program structure — with a permanent automated scan guarding against its reintroduction.
  • Added a reproducible BUILD_ID computed from the four executable modules, independent of line endings, verified by importing the production hashing implementation itself (not a duplicated test-side algorithm) from freshly generated source trees, and kept synchronized with the Help file on every source change.

Test Suite Growth

A new 89-test regression suite was created at kickoff and expanded to 123 automated tests across four rounds of independent review. The suite defines the four core module filenames and uses find_module_dir(start) to locate the nearest directory containing all four, so the same test file works from the canonical tests/ directory or when flattened beside the program modules; the flattened layout is exercised by a single isolated discovery smoke test rather than a second full run of the suite.

The final suite verifies the governing equations against an independent finite-difference and potential-maximization derivation; capture, escape, radial-infall, and circular-orbit outcomes; tangential launches on both sides of the photon sphere; the local kinematic bound and its floating-point boundary behavior; scale invariance, including a uniformly tiny but representable scale; extreme and invalid finite inputs; step-size convergence of Δφ and the final affine parameter; array and diagnostics consistency; plotting guardrails; output-file collision avoidance under both sequential and concurrent access; provenance-sidecar content and independent round-trip reproduction (including an exact-parsing status oracle immune to a CLI-option-name false positive); console-summary reproducibility; command-line error handling; Help-file structure, defaults, and scientific content; Python 3.10 syntax compatibility (verified by AST parsing, not by running under a second interpreter); reproducible BUILD_ID computation, independently exercised from real line-ending-normalized source trees; and freedom of the four core modules from reviewer/audit vocabulary. All 123 tests pass under CPython 3.11 in this environment, including a run with -W error::RuntimeWarning, with zero failures, errors, or skips.

Known Limitations

  • Intended for education and conceptual exploration of Schwarzschild null geodesics rather than research-grade relativistic ray tracing.
  • PhotonOrbit exposes a single calculation mode: integrating one photon (null-geodesic) trajectory in the equatorial plane per run. It has no multi-mode switch.
  • An escaping trajectory is stopped at the practical surface r = 2×r0, not integrated to literal spatial infinity.
  • The reported closest-approach radius is the smallest sampled point along the integrated path, not an interpolated turning point, and can show a little run-to-run jitter as the step size changes even though Δφ and the final affine parameter (which are event-interpolated) converge cleanly.
  • Horizon and escape-radius crossings are located by linear (first-order) interpolation within the final integration step; the underlying state integration itself is fourth-order Runge–Kutta, so event-location accuracy converges more slowly than the trajectory does between events.
  • The reported Δφ is the accumulated Schwarzschild-coordinate azimuth over a run's finite integration interval, not the conventional asymptotic light-deflection angle; no such angle is defined for a trajectory that reaches the event horizon.
  • The provenance sidecar and the console's "Reproduce this exact run with:" command reproduce the exact physics inputs and PhotonOrbit's own two rendering options (--dpi, --lw); they do not fix or record Matplotlib's own defaults (fonts, colors, backend, version), so an independently regenerated PNG is not guaranteed to be byte-identical to the original.
  • The local kinematic-bound check accepts an impact parameter within a few floating-point ulps of the true bound at a given starting radius, by design, to tolerate the small representational difference between two algebraically equivalent formulas used internally and in the Help file's own worked examples. See Known Minor Maintenance Items below.
  • BUILD_ID intentionally covers only the four executable modules (physics_photon.py, driver_photon.py, main.py, plot_photon.py); it does not change when the Help file or test suite changes.
  • The Help file loads MathJax from a public CDN. Offline, its prose and unrendered TeX source remain available, but equations are not typeset.

Known Minor Maintenance Items

  • The local kinematic-bound check's few-ulp tolerance still accepts a small number of representable impact-parameter values strictly above the exact bound at a given starting radius (four such values at the documented r0=3 circular-orbit case), each reported as the circular lambda_max outcome rather than rejected. The interval is a few parts in 1015 of the bound itself and does not affect any documented worked example. A future pass could tighten this by comparing against the maximum of the two algebraically equivalent bound formulas already used in the code and the Help file, rather than adding a fixed tolerance band on top of one of them.
  • Two recent Help-file documentation corrections — the rendering-reproducibility caveat and the Δφ-versus-deflection-angle distinction — do not yet have their own dedicated regression assertions, beyond a related check on the plotting module's own docstring. A future pass could add narrow semantic checks (for example, confirming specific key phrases remain present in the relevant Help sections) so that a future edit cannot silently drop either clarification.
  • The Help file's Δφ discussion currently describes the event horizon, the escape radius, and the lambda_max affine-parameter cutoff together as the run's "stopping surface." The first two are geometric surfaces; lambda_max is a termination condition on the affine parameter, not a spatial or spacetime surface, and the wording could be tightened to distinguish them.
