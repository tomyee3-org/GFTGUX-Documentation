WHAT THIS PROGRAM DOES, IN ONE PARAGRAPH
-----------------------------------------
GravitationalWaveSources is a small teaching program (four Python modules
plus a browser-based help file) that simulates the inspiral of two orbiting
compact objects (neutron stars or black holes) as they lose energy to
gravitational radiation and spiral together. It integrates the standard
"leading-order" (Newtonian quadrupole) frequency-evolution equation up to
the point where the orbit reaches the Schwarzschild innermost-stable-
circular-orbit (ISCO) frequency, and plots the resulting chirp: a
sinusoidal strain waveform whose amplitude grows and whose frequency rises
as the two objects approach each other. An optional add-on illustrates a
simplified post-cutoff "ringdown" (the damped oscillation of the merged
object settling down), clearly labeled as a toy extension rather than a
real merger model. Every plot is annotated with the run's key numbers
(chirp mass, ISCO frequency, time to ISCO, strain scale) and the program
is deliberately explicit, in both its printed output and its help file,
about which real-world effects (detector response, spin, eccentricity,
tides, redshift, higher-order corrections) are NOT included.

The five images in this folder were produced by simply running the
program from the command line with different options; nothing about the
underlying physics or plots was altered to make a nicer picture — these
are exactly what a student running the tutorial would see.

NOTE ON --outdir: in this delivery, passing --outdir <folder> makes the
program save a timestamped PNG copy of the figure into that folder IN
ADDITION to showing it on screen interactively (previously it replaced
the on-screen display). That is how these five sample PNGs were produced:
each command below also popped up an interactive window in the original
run, exactly as a student would see it.

HOW TO REPRODUCE EACH SAMPLE
-----------------------------
  1) python main.py --outdir <folder>
  2) python main.py --m1 36 --m2 29 --d 440 --outdir <folder>
  3) python main.py --m1 36 --m2 29 --d 440 --ringdown --t_before 0.2 --t_after 0.05 --outdir <folder>
  4a) python main.py --m1 36 --m2 29 --d 440 --dt 2e-4 --t_before 0.15 --outdir <folder>
  4b) python main.py --m1 36 --m2 29 --d 440 --dt 8e-4 --t_before 0.15 --outdir <folder>

Each command also produced a short console transcript (the "run summary"
printed to the terminal), included alongside the PNGs as .log files, so
you can see both the picture and the printed numbers side by side.


IMAGE-BY-IMAGE GUIDE
======================

01_default_BNS_1.4+1.4Msun_400Mpc.png
--------------------------------------
The program's default case: two 1.4-solar-mass neutron stars (a
binary-neutron-star, "BNS", system) at 400 Mpc, starting at 20 Hz.
This is the full ~158-second inspiral shown at once, so the individual
wave cycles near the start are too densely packed to see by eye (there
are roughly 3,000 of them before the cutoff) — that compression is itself
the point of the picture: it shows, at a glance, how the whole signal
sweeps from a very slow, faint hum up to a rapid, loud "chirp" in the
last fraction of a second, with the classic wedge-shaped envelope. The
three panels are: (top) the oscillating strain waveform with its dashed
amplitude envelope, (middle) that same amplitude envelope alone on its
own vertical scale, and (bottom) the rising gravitational-wave frequency,
flattening out at the labeled ISCO cutoff (1570.0 Hz here). This is the
picture a student sees just by running the program with no arguments.

02_BBH_36+29Msun_440Mpc_no_ringdown.png
-----------------------------------------
A heavier "binary black hole" (BBH) example, 36 + 29 solar masses at
440 Mpc — the mass combination associated with the first LIGO detection,
GW150914 (chosen here purely for pedagogical familiarity, not as an exact
model of that event). Because the whole inspiral only lasts about 0.8 s
in this leading-order model, individual wave cycles are now clearly
visible, and the chirp — both the rising frequency and the growing
amplitude — is easy to see directly in the top panel without any zooming.
This image is a good one to show anyone who has never seen a "chirp"
plot before.

03_BBH_36+29Msun_440Mpc_WITH_ringdown_zoomed.png
---------------------------------------------------
The same BBH system, now zoomed to the last 0.2 s before, and 0.05 s
after, the ISCO cutoff, with the optional --ringdown extension turned
on. The blue inspiral waveform hands off, continuously in amplitude and
phase, to a red damped-oscillation "ringdown" immediately after the
dotted ISCO-cutoff line. This ringdown is explicitly a toy model (a
non-spinning remnant retaining 95% of the total mass) — the help file and
console output both say so — but it is useful for showing students what
a ringdown looks like and how its frequency and decay time are read off
the plot (annotated in the top-right corner: f_QNM = 195.5 Hz,
tau_QNM = 3.418 ms).

04a / 04b — convergence pair (dt = 2e-4 s vs. dt = 8e-4 s)
--------------------------------------------------------------
The same BBH system and the same 0.15 s zoom window, run twice with two
different integration timesteps. This pair is included specifically to
show the program's built-in numerical-convergence exercise (see the help
file's EXP-7): as the timestep shrinks, the plotted waveform's late-time
phase stabilizes, which is exactly the kind of check the program invites
students to do for themselves via its printed "Time to ISCO" diagnostic.
It is also a demonstration that the program actively guards against a
timestep that is far too coarse: a much larger --dt than either of these
(e.g. 50 s) is rejected outright, with an explanatory error, rather than
silently producing a meaningless answer.

WHAT TO LOOK FOR OVERALL
--------------------------
Across all five images: the chirp shape (rising frequency and amplitude)
is immediately recognizable without any specialist knowledge; the
program is explicit on-screen and in its help file about being a
leading-order teaching model rather than a matched-filter template; and
the printed run summaries (in the accompanying .log files) give the key
physical numbers — chirp mass, total mass, ISCO frequency, time to ISCO,
and the strain scale — for each configuration, letting a reader connect
the picture directly to the underlying equations described in the help
file.
